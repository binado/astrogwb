# astrogwb examples

Runnable, self-contained scripts using only `astrogwb` and its dependencies.
Nothing here imports `astrogwb_paper` or assumes a repository checkout, so each
example works against a plain `pip install astrogwb`.

## `h0_mcmc.py` — infer H₀ with NUTS

Loads a `waveform_catalog` file, builds the observed stochastic-background
spectral density from it, and samples H₀ with every other hyperparameter pinned
at its fiducial value.

```bash
python h0_mcmc.py CATALOG.h5 -o chains.nc
```

A quick run that finishes in about a minute on a laptop:

```bash
python h0_mcmc.py CATALOG.h5 -o chains.nc \
    --max-catalog-samples 512 --num-warmup 50 --num-samples 100
```

`python h0_mcmc.py --help` lists every option. The ones that matter most:

| Flag | Default | Why you would change it |
|---|---|---|
| `--detectors` | `E1 E2 E3` | Any names from `astrogwb.detector`'s sensitivity table. Needs at least two — the effective PSD is a cross-correlation sum. A 2G network such as `H1 L1 V1` will not constrain H₀: the background is far below its noise, so the posterior just returns the prior. |
| `--max-catalog-samples` | all | Production banks hold 16k–32k sources across 4097 frequency bins. Each NUTS step contracts that whole `(F, N)` array, so subsampling is the main runtime knob. |
| `--f-min` / `--f-max` | `10` / `2048` Hz | Bins where no detector pair contributes are dropped automatically, so widening the band is safe. |
| `--num-chains` | `1` | More than one chain gives you an `r_hat` in the summary. |

### One catalog, used twice

The script uses the same catalog as both the *injection* (the simulated
observation) and the *importance-sampling proposal*. The reference weights
model computes

```
log w = log p(z|θ) − log q(z) − 2 Δlog d_L
```

and the script derives the proposal density `q` from the same fiducials that
build the injection. Every weight is then exactly 1 at θ = θ_fid, so the
"observed" spectrum reduces to the unweighted catalog contraction and the true
H₀ is known to sit at `FIDUCIALS["H0"]` (67.66). The run prints the mean
relative effective sample size next to the posterior summary; it should be very
close to 1, and a collapsed value is the characteristic failure of importance
reweighting.

The injection carries no noise realization, so the posterior should recover the
fiducial tightly. A noise draw would shift it by roughly 1σ and make a correct
script look broken.

Production analyses instead draw two *independent* catalogs, which is what
makes the weights informative. See the `astrogwb-paper` workspace project in
the source repository.

### Getting a catalog

Any file in the `waveform_catalog` format works — see
`astrogwb.waveform.catalog` for the layout, and `make_catalog` / `save_catalog`
for building one from arrays. Catalogs must carry `redshift` and
`luminosity_distance` in their `source_parameters`, and the distances must come
from the same cosmology as the fiducials, since the weights compare the two.

In the source repository, the files under
`packages/astrogwb-paper/outputs/catalogs/*.h5` are valid inputs, generated by
the `astrogwb-generate-bank` console script in the paper package.

### Output

Chains are written as an xarray netCDF file with `(chain, draw)` dimensions,
holding `H0` plus the model's `total_merger_rate` and
`importance_relative_ess` deterministics, and the run's configuration in the
dataset attributes:

```python
import xarray as xr

chains = xr.open_dataset("chains.nc", engine="h5netcdf")
print(chains.H0.mean(), chains.attrs["fiducial_H0"])
```

The layout is what `arviz.from_dict` expects, so it loads directly into arviz
if you have it — the example itself never imports it.
