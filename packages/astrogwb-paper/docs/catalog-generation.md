# Generating catalogs

The catalog pipeline has three stages:

1. **source populations** are finite parameter tables generated by
   [`gwmock-pop`](https://leuven-gravity-institute.github.io/gwmock-pop/);
2. **production populations** are assembled from source populations by an
   identity, subsample, or mixture operation;
3. **waveform catalogs** contain the frequency-domain polarizations generated
   only for the selected production rows.

This separation keeps cheap population generation and selection independent
from expensive waveform generation.

## Source populations

The fiducial source graph is
[`inputs/populations/bns_population.yaml`](../inputs/populations/bns_population.yaml). The uniform
guard graph is
[`inputs/populations/bns_population_uniform_redshift.yaml`](../inputs/populations/bns_population_uniform_redshift.yaml).
They must differ only in the redshift sampler. All other distributions and
redshift-dependent transforms are identical, because the current importance
ratio explicitly contains only the redshift proposal density.

Source pools are ordinary `gwmock-pop` outputs:

```bash
uv run gwmock-pop simulate \
  --config inputs/populations/bns_population.yaml \
  --n 32768 \
  --output outputs/populations/sources/proposal-fiducial.h5 \
  --seed 42

uv run gwmock-pop simulate \
  --config inputs/populations/bns_population_uniform_redshift.yaml \
  --n 32768 \
  --output outputs/populations/sources/proposal-uniform-redshift.h5 \
  --seed 43
```

The independent injection uses a separate fiducial source pool and seed.

## Production populations

`astrogwb-assemble-population` composes source files. Its operations are:

- `identity`, preserving every source row;
- `subsample`, selecting seeded rows without replacement;
- `mixture`, drawing a categorical component for each output row and then a
  seeded source row without replacement from that component.

The committed proposal is

$$
q(z)=(1-\epsilon)p_{\rm fid}(z)
     +\epsilon\,\mathcal{U}(z_{\min},z_{\max}),
\qquad \epsilon=0.20.
$$

Its explicit assembly command is:

```bash
uv run astrogwb-assemble-population \
  --operation mixture \
  --source outputs/populations/sources/proposal-fiducial.h5 --weight 0.8 \
  --source outputs/populations/sources/proposal-uniform-redshift.h5 --weight 0.2 \
  --source-config inputs/populations/bns_population.yaml \
  --source-config inputs/populations/bns_population_uniform_redshift.yaml \
  --uniform-redshift-fraction 0.2 \
  --num-samples 16384 --seed 142 \
  --output outputs/populations/production/proposals/bns-n16384-df1.h5
```

The assembler stores `proposal_component` and
`proposal_redshift_logpdf` for every proposal row. The latter is the analytic
mixture denominator evaluated with `logaddexp`, not an empirical histogram or
the density of only the component that generated the row.

The shared synthetic observation is an independently seeded, 32,768-sample
fiducial production population. It is never reused as the importance proposal.

## Waveform catalogs

Production populations are passed unchanged to the existing waveform command:

```bash
uv run astrogwb-generate-waveform-catalog \
  --population outputs/populations/production/proposals/bns-n16384-df1.h5 \
  --output outputs/catalogs/proposals/bns-n16384-df1.h5 \
  --approximant IMRPhenomXAS_NRTidalv3 \
  --sampling-frequency 8192 \
  --minimum-frequency 2 \
  --maximum-frequency 4096 \
  --reference-frequency 20 \
  --frequency-resolution 1 \
  --chunk-size 2048
```

The output is a [`pluscross`](https://pypi.org/project/pluscross/) HDF5
catalog. All production columns, including the proposal density, are preserved
as source parameters.

## Inventory and workflow

[`inputs/catalogs.yaml`](../inputs/catalogs.yaml) declares source pools, the
shared injection recipe, named proposal recipes, and waveform settings.
Proposal recipes must specify `uniform_redshift_fraction`; there is no implicit
epsilon.

Experiments select a named proposal recipe, for example
`catalog: bns-n8192-df1`. All experiments use the same independent injection
catalog. Catalog generation remains an explicit workflow prerequisite; see
[Snakemake workflow](./snakemake-workflow.md#catalog-workflow).
